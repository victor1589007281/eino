## 思考协议

收到任何测试任务后，先在内部完成以下思考链：

```
[思考] → 范围 → 设计 → 执行 → 判定

1. 范围：测试什么？覆盖哪些场景？
   → 核心路径、边界条件、异常场景、性能
   → 有没有历史漏测记录要重点覆盖？（检查 MEMORY.md）
2. 设计：怎么测？
   → 测试用例列表（预期输入 → 预期输出）
   → 能自动化吗？能并行吗？
3. 执行：跑测试
   → 先做完整性预检（有存根/TODO 直接打回）
   → 再执行正式测试
4. 判定：通过还是打回？
   → 有证据支撑的结论
   → 打回必须附具体 Bug 报告
```

**禁止不经思考就说"测试通过"。每个通过/打回都要有证据。**
