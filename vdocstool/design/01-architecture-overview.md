## 3. 核心设计原则

### 3.1 分层解耦
- **MCP 层**：协议处理，工具暴露
- **工具层**：业务逻辑，流程编排
- **算法层**：智能能力，可插拔替换
- **存储层**：数据持久化，索引管理

### 3.2 策略模式
所有智能组件支持多策略切换：
- 在线/离线模式
- 精度/速度权衡
- 成本/效果平衡

### 3.3 优雅降级
```
LLM 服务不可用 → ML 本地模型
ML 模型加载失败 → 规则引擎
全部失败 → 基础关键词匹配
```

## 4. 数据流图

### 4.1 意图识别流程
```
用户输入
    │
    ▼
┌─────────────────┐
│ 预处理          │ ← 分词、标准化
└────────┬────────┘
         │
    ┌────┴────┐
    │ 路由决策 │ ← 根据配置选择引擎
    └────┬────┘
         │
    ┌────┼────────────────┐
    ▼    ▼                ▼
  Rule  ML              LLM
    │    │                │
    └────┴───────┬────────┘
                 ▼
         ┌──────────────┐
         │ 结果融合      │ ← 多模型投票/加权
         └──────────────┘
                 │
                 ▼
         IntentResult
```

```
查询输入
    │
    ▼
┌─────────────────┐
│ 意图解析        │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 多通道召回      │
│ ┌─────┬─────┐   │
│ │倒排 │向量 │   │
│ │索引 │索引 │   │

         │
         ▼
┌─────────────────┐
│ 重排序          │ ← Cross-Encoder / LLM

         │
         ▼
    检索结果
```

## 5. 性能指标目标

| 指标 | L1 | L2 | L3 |
|------|----|----|-----|
| 读延迟 | <5ms | <50ms | <500ms |
| 写延迟 | <10ms | <100ms | <1s |
| 召回率 | 100% | >90% | >85% |
| 容量 | 10-20条 | 7-30天 | 无限 |

## 6. 技术选型

| 组件 | 主选方案 | 备选方案 |
|------|---------|---------|
| 意图识别 | Claude API | 本地 BERT |
| 向量化 | OpenAI text-embedding-3 | BGE-M3 |
| 倒排索引 | Elasticsearch | Bleve |
| 向量数据库 | Milvus | Pinecone |
| 图数据库 | Neo4j | ArangoDB |
| 缓存 | Redis | 本地内存 |
| 对象存储 | S3 | MinIO |
