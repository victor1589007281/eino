# VDocsTool 设计方案总结

## 1. 核心改进点

### 1.1 意图识别升级

| 方面 | 现状 | 改进方案 |
|------|------|---------|
| **识别方式** | 正则匹配 + 关键词 | ML分类 + LLM理解 + 规则降级 |
| **准确率** | ~70% | 目标 >90% |
| **可扩展性** | 需手动维护规则 | 模型可训练，Prompt可配置 |
| **上下文理解** | 无 | LLM 支持多轮上下文 |

### 1.3 架构层次优化

```
改进前：工具直接实现智能逻辑
┌─────────────────────────────────────────┐
│  Email Tool                             │
│  ├─ 正则意图解析 (内嵌)                  │
│  └─ 关键词匹配 (内嵌)                    │
└─────────────────────────────────────────┘

改进后：智能能力抽离到算法层
┌─────────────────────────────────────────┐
│  Email Tool                             │
│  └─ 调用算法层 API                       │
└────────────────┬────────────────────────┘
                 │
┌────────────────▼────────────────────────┐
│  Algorithm Layer                         │
│  ├─ Intent Engine (ML/LLM/Rule)         │
│  ├─ Embedding Engine (向量化)            │
│  ├─ NLP Pipeline (分词/NER/摘要)         │
│  └─ Index Engine (倒排/向量/图)          │
└─────────────────────────────────────────┘
```

## 2. 技术选型总结

| 组件 | 选型 | 理由 |
|------|------|------|
| **意图识别-快速** | FastText | 轻量、推理快、Go支持好 |
| **意图识别-精准** | OpenAI/Claude API | 效果最佳、支持上下文 |
| **向量化** | OpenAI text-embedding-3 | 效果好、稳定、成本可控 |
| **向量化-备选** | BGE-M3 | 本地部署、多语言、免费 |
| **倒排索引** | Elasticsearch | 功能强大、中文分词好(IK)、分布式 |
| **向量数据库** | Milvus | 已规划、功能全、开源 |
| **图数据库** | Neo4j | 已选用、成熟稳定 |

## 4. 关键指标

### 4.1 性能指标

| 指标 | 目标值 |
|------|--------|
| 意图识别-规则 | <1ms |
| 意图识别-ML | <20ms |
| 意图识别-LLM | <500ms |
| 向量化 (单条) | <100ms |
| 向量化 (批量100条) | <1s |
| 倒排检索 | <20ms |
| 向量检索 | <50ms |
| 混合检索 | <100ms |

### 4.2 质量指标

| 指标 | 目标值 |
|------|--------|
| 意图识别准确率 | >90% |
| 意图识别召回率 | >85% |
| 检索 Recall@10 | >90% |
| 检索 Precision@10 | >80% |

## 5. 风险与应对

| 风险 | 影响 | 应对策略 |
|------|------|---------|
| LLM API 不稳定 | 意图识别失败 | ML + 规则降级 |
| 向量 API 超时 | 语义检索失败 | 缓存 + 关键词降级 |
| 模型效果差 | 意图识别不准 | 持续收集数据迭代 |
| 索引数据不一致 | 检索结果不全 | 事务写入 + 定期同步 |
