# Memory Skill 使用指南

## 概述

记忆工具提供全局上下文管理能力，采用三级存储架构（L1热/L2温/L3冷），支持智能检索和自动归档。

## 架构说明

```
┌─────────────────────────────────────────────────────────────┐
│                    L1 工作记忆区 (Hot)                        │
│  存储: Redis | 容量: 20条消息/4000 tokens | 延迟: <1ms        │
└─────────────────────────────────────────────────────────────┘
                              ↓ 容量超限/主题切换
┌─────────────────────────────────────────────────────────────┐
│                   L2 短期记忆区 (Warm)                        │
│  存储: 向量DB+关系DB | 容量: 7-30天 | 延迟: 5-20ms            │
└─────────────────────────────────────────────────────────────┘
                              ↓ 30天无访问
┌─────────────────────────────────────────────────────────────┐
│                   L3 长期记忆区 (Cold)                        │
│  存储: S3+Neo4j | 容量: 无限 | 延迟: 100-500ms               │
└─────────────────────────────────────────────────────────────┘
```

## 工具列表

### 1. store_memory - 存储记忆

存储消息到记忆系统，自动分层管理。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_id | string | 是 | 会话ID |
| role | string | 是 | 角色(user/assistant/system) |
| content | string | 是 | 消息内容 |
| topic_id | string | 否 | 主题ID |

**使用示例：**
```json
{
  "session_id": "session_001",
  "role": "user",
  "content": "如何使用Python实现异步HTTP请求？"
}
```

**返回：**
```json
{
  "message_id": "msg_xxx",
  "tier": "L1",
  "token_count": 25,
  "archive_triggered": false
}
```

### 2. retrieve_context - 检索上下文

多层检索并组装上下文，用于增强AI回复。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| query | string | 是 | 查询内容 |
| session_id | string | 是 | 会话ID |
| token_budget | integer | 否 | Token预算，默认4000 |
| topic_id | string | 否 | 锁定的主题ID |

**返回结构：**
```json
{
  "context": [
    {
      "content": "之前讨论的内容...",
      "role": "assistant",
      "source": "L1",
      "relevance": 0.95
    }
  ],
  "sources": [...],
  "total_tokens": 1234,
  "recall_stats": {
    "l1_hit_count": 5,
    "multi_channel_results": 10
  }
}
```

### 3. switch_topic - 切换主题

切换到新主题，将当前L1内容归档到L2。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| session_id | string | 是 | 会话ID |
| new_topic | string | 否 | 新主题标题 |

**使用场景：**
```
用户: "好的，这个话题先放一放，我们来讨论另一个问题"
Agent: 调用 switch_topic 归档当前对话
```

### 4. recall_topic - 召回主题

召回历史主题到当前会话。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| topic_query | string | 是 | 主题查询 |
| session_id | string | 是 | 会话ID |

**使用场景：**
```
用户: "回到我们之前讨论的Redis缓存方案"
Agent: 调用 recall_topic 召回相关上下文
```

### 5. get_entity_relations - 获取实体关系

查询知识图谱中的实体关系。

**参数：**
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| entity_name | string | 是 | 实体名称 |
| depth | integer | 否 | 关系深度，默认2 |

### 6. summarize_session - 会话摘要

生成当前会话的摘要。

### 7. archive_session - 手动归档

手动将会话归档到长期存储。

### 8. get_capacity_stats - 容量统计

获取记忆系统的容量统计信息。

## 检索管道详解

### 五层检索流程

```
用户输入
    │
    ▼
┌──────────────────┐
│ 第1层: 意图解析   │  识别是否需要历史上下文
└──────────────────┘
    │
    ▼
┌──────────────────┐
│ 第2层: L1匹配    │  检查工作记忆相似度
└──────────────────┘
    │ 相似度<0.8
    ▼
┌──────────────────┐
│ 第3层: 多路召回   │  4通道并行检索
│  • 向量语义 40%   │
│  • 实体图谱 30%   │
│  • 时序邻近 20%   │
│  • 用户锁定 10%   │
└──────────────────┘
    │
    ▼
┌──────────────────┐
│ 第4层: 重排序    │  精排+时间衰减+去重
└──────────────────┘
    │
    ▼
┌──────────────────┐
│ 第5层: 上下文组装 │  Token预算分配
└──────────────────┘
```

### 意图解析示例

| 用户输入 | 解析结果 |
|----------|----------|
| "继续之前的话题" | 显式主题切换 → 需要历史 |
| "刚才说的Redis方案" | 引用检测 → 需要历史 |
| "Python怎么读文件？" | 独立问题 → 可能需要历史 |
| "换个话题，我想问..." | 新话题指示 → 不需要历史 |

## 容量管理

### 自动归档触发条件

| 条件 | 阈值 | 动作 |
|------|------|------|
| L1消息数 | ≥ 20条 | 归档到L2，保留最近5条 |
| L1 Token数 | ≥ 4000 | 归档到L2，保留最近5条 |
| L2访问时间 | > 30天 | 迁移到L3 |

### 归档策略

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **auto** | 自动选择 | 默认，推荐使用 |
| **full** | 完整归档 | 重要对话，需要保留所有细节 |
| **incremental** | 增量归档 | 中等大小对话 |
| **summary** | 仅摘要 | 大量对话，只需保留要点 |

## 使用最佳实践

### 1. 何时存储记忆

```
✅ 应该存储:
- 用户的每个问题
- AI的每个回答
- 重要的工具调用结果

❌ 不需要存储:
- 系统提示词
- 临时的中间状态
```

### 2. 何时检索上下文

```
✅ 应该检索:
- 用户引用之前的对话："刚才说的..."
- 继续讨论某个主题
- 复杂的多轮对话

❌ 不需要检索:
- 独立的简单问题
- 明确的新话题开始
```

### 3. 主题管理

```
# 检测到话题转换时
if 用户说"换个话题" or 用户说"另外一个问题":
    调用 switch_topic()

# 用户想回顾之前的讨论时
if 用户说"之前讨论的" or 用户说"回到":
    调用 recall_topic(topic_query="关键词")
```

### 4. Token预算分配

```
默认预算: 4000 tokens

分配策略:
- 60% 给高相关度内容（最重要）
- 30% 给中等相关度内容（补充）
- 10% 缓冲区（安全余量）
```

## 故障排除

### Q: 检索结果不相关？
A: 尝试：
1. 增加 token_budget
2. 使用更具体的查询
3. 指定 topic_id 锁定主题

### Q: 归档过于频繁？
A: 调整配置：
```json
{
  "memory": {
    "l1": {
      "max_messages": 30,
      "max_tokens": 6000
    }
  }
}
```

### Q: 历史记录找不到？
A: 检查：
1. 是否已归档到L3（超过30天未访问）
2. 使用 get_capacity_stats 查看存储状态
3. 尝试用不同关键词 recall_topic
